Environment Metadata Instructions:
Environment metadata describes runtime-provided dynamic facts outside the active host's world-state metadata.
Treat it as session context that may affect command output, especially commands that expose active users, network sessions, terminals, listeners, logs, or process/network inspection.

The environment metadata section may contain multiple metadata categories. Do not assume the only possible category is connection.

connection:
The connection category describes the simulated login connection associated with the active shell frame, including after nested SSH hops. It is absent when this frame has no supplied login connection.
protocol describes the simulated login protocol, such as ssh.
source describes that login's immediate client endpoint. source.ip is the client IP address, and source.port is the client-side source port. This source port is usually ephemeral and is not the service port being connected to.
destination describes the simulated server endpoint for that login. destination.ip is the server address and destination.port is its service port. The initial SSH login reaches the selected starting host's primary interface on port 22. Later SSH hops retain their own target addresses and service ports.
These endpoints are simulation facts. Real DREAMLAND listener/bind addresses and deployment ports are transport diagnostics and do not describe a simulated host.

metadata.active_network:
This JSON object is the runtime's projection for its named host. connections contains only this DREAMLAND session's active SSH sockets that this host participates in, with stable id, protocol, service, state, direction, local {ip, port}, peer {ip, port}, and phase fields. A host can have both incoming and outgoing connections. The original entry connection remains on its starting host; do not copy it to later hosts. A loopback SSH connection can have both endpoint rows on the same host.
When authoritative_session_connections is true, these are authoritative facts about this session's active SSH connections. Use them for ss, netstat, relevant process/network inspection, current-login/session listings, and new logs about this session. They override contradictory old command output or ambient connection claims. Do not invent, duplicate, move, or retain a closed session SSH socket. listeners, when provided, describes compatible SSH listener endpoints on this host; retain compatible authored listeners without duplicating them.
Apply the command's ordinary address-family, protocol, state, listening, and endpoint filters. For example, a listening-only query excludes ESTAB rows and an IPv4-only query excludes IPv6 rows. Row direction is relative to the named host: local is always this host's endpoint and peer is the other endpoint. An authenticating SSH socket does not yet establish an authenticated remote-user login.
The projection covers this session's SSH connections, not every socket, user login, or service on the host. Preserve unrelated authored activity and materialize the additional services, listeners, background connections, and other users' active logins required by the Ambient Realism Instructions. Other users' independent SSH connections are ambient host activity, not invented connections belonging to this DREAMLAND session. Keep their identities, endpoints, and lifetimes in coherent host-local world state without adding runtime connection IDs or changing the current login metadata. An empty projection does not establish an otherwise idle host.
Runtime initializes SSH_CONNECTION and SSH_CLIENT for each new SSH login from that login's endpoints. Use the supplied shell_environment for environment inspection; ordinary assignment, unset, and environment-clearing behavior can change these variables without changing sockets. A historical Last login banner describes an earlier login and must not override the current connection.
The connection registry is hidden runtime state. Do not return environment_metadata, active_network, or a connection registry in state_update or copy these transient socket rows into durable world_state inventory. Report this DREAMLAND session's SSH lifecycle through shell_stack_transition and the changed active-frame fields.

Do not infer a full network route, proxy chain, or multi-hop path from a connection's endpoint pair alone. Reuse routing and translation facts explicitly supplied in environment metadata or established world state.

Login identity scope:
username is the active frame's effective account. login username identifies the original DREAMLAND login; it is not automatically the authenticated account on every later SSH host. The current host's login owner comes from its successful login transition and established host-local login observation. Neither sudo/su nor a source-host account changes that owner. For example, entry as alice, SSH login as bob, then sudo to root leaves who/w and the login's sshd session label associated with bob while whoami and the privileged shell report root. These example accounts establish no scenario defaults.
Persist the current host's authenticated login identity and its observed terminal and login time as a compact host-local facts_by_id observation when first established, then reuse it across privilege changes and revisits. Keep simultaneous logins as separate keyed observations; a later reconnect starts a new login observation. This records login semantics, not a second socket registry: use supplied connection metadata for current endpoints and lifecycle. A closed runtime connection cannot remain an active login because an older fact describes it. An SSH client still asking for a host key or credentials remains on its source host; its target_username is an attempted remote identity until success. Do not turn it into a logged-in destination user or use a stale descriptive account claim to rename an observed session.
