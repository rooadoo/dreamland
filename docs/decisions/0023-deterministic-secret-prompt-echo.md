# 0023 Deterministic Secret Prompt Echo

Status: Active
Audience: maintainers, DREAMLAND operators, and coding agents
Purpose: record why DREAMLAND hides secret-prompt input in the terminal runtime
instead of asking the command agent to control echo behavior.

## Overview

DREAMLAND command output is generated by built-ins or model-backed agents, but
terminal line editing and byte echo are transport/runtime behavior. During SSH
and sudo password prompt testing, two defects appeared together: the prompt was
rendered twice, and typed password text was echoed visibly into the terminal.

The runtime now recognizes secret prompts for active `ssh` and `sudo`
interactive programs from structured state and prompt text. Matching prompts
use a non-echoing line editor, and command output that already ends with the
active secret prompt is not followed by an additional transport-rendered prompt.

## Decision

DREAMLAND deterministically suppresses local terminal echo for recognized
secret-prompt states. This behavior belongs in the terminal runtime, not in the
LLM prompt or as an agent-controlled output convention.

The current recognition path is intentionally conservative. The active
interactive program must be one of the supported programs, currently `ssh` or
`sudo`, and either its metadata phase or rendered prompt must indicate password,
passphrase, or similar secret entry.

This may miss future programs that request secrets, such as database clients,
VPN tools, package managers, or custom administrative scripts. Those programs
should be added to deterministic runtime recognition when they become part of
the supported emulation surface. They should not require broader prompt
complexity or model-specific instructions to prevent echoing secrets.

## Consequences

This takes terminal echo decisions partly out of the LLM's creative control.
That is acceptable for secret entry because visible passwords break basic
terminal realism and create confusing transcripts.

The tradeoff is explicit allow-list maintenance. A new secret-prompting program
can be missed until a test or user report identifies it. When adding such a
program, update `program_uses_secret_input`, add focused shell-session coverage,
and align `docs/AGENT_STATE.md` or prompt state-contract guidance when the
program requires a specific interactive state shape.

## Maintenance

Update this record if DREAMLAND replaces allow-listed secret prompt handling
with a more general terminal-attribute model, if secret echo handling moves out
of the SSH shell runtime, or if the emulator starts exposing model-controllable
terminal echo modes as part of `CommandStateUpdate`.
